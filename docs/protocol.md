# Integration protocol v1

[Manual home](README.md) · [Python SDK](integrations.md#python-sdk)

Launch the CLI with `integrate`. Exchange one JSON object per line, UTF-8, over stdin/stdout. Every message has a string `type`. Write logs to stderr. Flush each outgoing message and keep reading while tool callbacks run. The server rejects lines larger than 4 MiB of UTF-8 content and ignores blank lines.

## Message reference

Every field below is in addition to `type`. Use unique IDs and preserve them exactly in replies. Optional nullable event fields may be omitted by serialization.

| Direction | Type | Fields |
| --- | --- | --- |
| Client → server | `handshake` | `protocol_version` (1), optional `client` string |
| Server → client | `handshake_ok` | `protocol_version` |
| Server → client | `handshake_error` | `reason` |
| Client → server | `load` | `load_id`, `path` |
| Server → client | `loaded` | `load_id`, `tools` array |
| Server → client | `load_error` | `load_id`, `diagnostics` array |
| Client → server | `run` | `execution_id`, `path`, `input`; optional `provider`, `provider_config` |
| Server → client | `run_started` | `execution_id` |
| Server → client | `tool_request` | `execution_id`, `request_id`, `tool`, `input` |
| Client → server | `tool_response` | `request_id`, `output` |
| Client → server | `tool_error` | `request_id`, `error` |
| Server → client | `event` | `execution_id`, `event` object |
| Server → client | `result` | `execution_id`, `output` |
| Server → client | `run_error` | `execution_id`, `error` |
| Client → server | `cancel` | `execution_id` |
| Server → client | `protocol_error` | `reason`, `fatal` |

`tools` entries contain `name`, `input`, and `output`. Each field descriptor contains only `name`, `kind`, and `required`. The underlying kind enum includes `String`, `Bool`, `Int`, `Decimal`, `List`, `Schema`, and `Enum`, but the current server converter emits only String/Bool/Int/Schema and always sets required to true. Decimal becomes String and non-primitive references become Schema. This wire metadata does not describe nullability, enum symbols, nested fields, or element types; do not treat it as a complete schema interchange format. Complex declarations can load but fail registration when run.

Diagnostic entries contain `severity` and `message`, with an optional `code`. The current server constructs a null code, which its serializer omits, and a formatted message containing diagnostic details (or just an exception message). Do not assume a structured source-location field.

Event objects contain `kind`, `message`, `timestamp`, and optional `operation_id`, `call_id`, `duration_ms`, `parent_operation_id`, and `activation_id`. Timestamps are ISO-formatted UTC timestamps. Wire events omit the C# event's sequence, step ID, and attempt ID.

## Successful tool execution

The following is an illustrative exchange for `examples/docs/tools.mail`. Replace the path with an actual absolute path. Send each client line at the corresponding stage; server messages are shown separately. The symbolic IDs are opaque example strings.

Client handshake:

```json
{"type":"handshake","protocol_version":1,"client":"manual-example"}
```

Server:

```json
{"type":"handshake_ok","protocol_version":1}
```

Client load:

```json
{"type":"load","load_id":"load-1","path":"C:/path/to/MAILang/examples/docs/tools.mail"}
```

Server:

```json
{"type":"loaded","load_id":"load-1","tools":[{"name":"Echo","input":[{"name":"text","kind":"String","required":true}],"output":[{"name":"text","kind":"String","required":true}]}]}
```

Client run:

```json
{"type":"run","execution_id":"run-1","path":"C:/path/to/MAILang/examples/docs/tools.mail","input":{"text":"hello"},"provider":"simulated"}
```

Server (the real request ID is generated by the runtime):

```json
{"type":"run_started","execution_id":"run-1"}
{"type":"tool_request","execution_id":"run-1","request_id":"request-1","tool":"Echo","input":{"text":"hello"}}
```

The client executes Echo and replies with that request ID:

```json
{"type":"tool_response","request_id":"request-1","output":{"text":"hello"}}
```

After execution, the server emits its event batch, then:

```json
{"type":"result","execution_id":"run-1","output":{"text":"hello"}}
```

An illustrative event from that batch:

```json
{"type":"event","execution_id":"run-1","event":{"kind":"execution.started","message":"Workflow 'DirectTool' started.","timestamp":"2026-09-10T12:00:00.0000000+00:00"}}
```

## Failures, cancellation, and concurrency

The first message must be a version-1 handshake. Version mismatch produces `handshake_error`. Malformed JSON before handshake or an unexpected first message produces a fatal protocol error. After handshake, malformed JSON and unknown types generally produce nonfatal errors. Repeated handshake produces a fatal error; clients should terminate their session on any `fatal: true` response.

For a callback failure, send `{"type":"tool_error","request_id":"request-1","error":"explanation"}`. Compilation failures during load use `load_error`; compilation failures during run and execution failures use `run_error`. A run can fail before `run_started`.

Send `{"type":"cancel","execution_id":"run-1"}` to request cancellation. There is no separate cancel acknowledgment. Await terminal output rather than assuming dispatch stopped immediately; completed external effects are not rolled back. Unknown execution cancellation is ignored. Late or unknown tool replies are ignored with a stderr warning.

Multiple runs can overlap in one process. Correlate load responses by `load_id`, executions by `execution_id`, and callbacks by `request_id`. Duplicate active execution IDs are rejected. Events from different runs can interleave, and event delivery is batched after each execution rather than streamed during it.

Load is an inspection operation, not a saved executable handle. Run takes the path again and recompiles; it does not reference `load_id`. Every declared tool, including imported/unused tools, is returned by load and registered as a remote tool during run. Provider options are described in [integrations](integrations.md#provider-configuration).

Closing stdin triggers cancellation and shutdown of active executions and pending callbacks. Keep stdout exclusively for protocol JSON in any custom host implementation.
